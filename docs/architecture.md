# 架构和数据语义

```text
操作系统定时器 → daily-log → 文件锁 → Go 业务流程
                                  ├─ 独立采集器 → ActivityEvent → SQLite
                                  ├─ ReadingSession 推断
                                  ├─ 规则 / 可选 AI 摘录 → 每日日记
                                  └─ Sheets 按键定位 → 保护检查 → 单元格更新
```

## 存储

`events.payload` 包含 `ActivityEvent` 的完整字段，`raw` 保存来源快照和原始时间，`metadata` 保存论文/附件关联、作者、页码或任务项目等。表中额外索引 `source/day/timestamp` 用于查询。

`event_revisions` 在同一事件内容改变时保存旧快照，既不会把快照当成源系统完整历史，也不会因增量更新丢弃已看到的关联。`reading_sessions` 缓存推断结果；补采导致聚合变化时，旧会话保留并标记已被替代，避免工作表中留下未说明的过时推断。

`sync_state` 保存每个来源最后成功时间、状态、错误、预留 cursor 和诊断详情。当前 Zotero 使用每日全量枚举，Todoist/Calendar 使用带重叠范围的日期分页；不依赖跨次运行的分页 cursor。只在完整遍历和事务成功后前进来源水位。

`jobs` 记录采集与生成的全局成功时间，`dirty_days` 标记事实变动影响的日期，`journals` 保存生成稿和输入指纹，`sheet_snapshots` 保存本程序最后写入远端的整行快照，`suggestions` 是不覆盖人工内容的补充建议队列。SQLite 开启 WAL，等待数据库锁 30 秒，跨进程任务另用操作系统文件锁串行化。

## 幂等和时间

Zotero 事件键包含本地实例标识（可用时）、库、条目 key 及创建/最后修改类型。Todoist 使用完成事件 ID，不能只用 task ID。Calendar 使用日历 ID、实例 ID 和切分后的北京时间日期。主动对话导入使用本人提供的稳定 ID。

事件日期来自转换后的来源时间，不来自采集时间。旧版 Zotero 不带时区的 SQL 时间按 UTC 解释，Calendar 没有 offset 时使用对应 `timeZone`，全天日期按北京时间处理。原始值仍保存在 JSON 中。

回查起点取「今天零点减 3 天」与「该来源最后成功时间减 3 天」中更早者；`--since` 只能扩大范围。长时间关机后不会只看最近三天。但源端已删除、历史受套餐限制或从未暴露的活动无法凭空恢复。

## 整理与保护

先做显式来源关联去重，再按证据强度分组同主题，三时段文本保留准确时间及来源。论文会话依据创建标注，不把修改时间当作额外新标注。修改快照另行显示。跨时段候选会话同时出现在相关时段栏，但计数按原始唯一事件计算。

生成前确保最近一次应执行的 23:00 采集已成功；若不满足则立即补采。某个来源失败时其他来源可入库，日记生成退出失败并等待系统重试，避免将缺失数据当成完整日记。系统恢复任务可以立即生成补采稿；正常定时任务在 23:00 依次采集、总结当天日志并同步。

Sheets 每次读取元数据和实际表头，500 行一批检查键，发现已有重复日期、缺失表头或歧义字段时停止。写前再次读取目标行；只写受管理字段，用 `RAW` 避免来源文本被当成公式。确认、手动补充和人工改动触发保留与建议；未知来源的非空行也按人工内容处理。既有表格排序、插列不会被固定列号破坏；列变动导致快照不能匹配时采用保守保护。

本机文件锁防止本机多任务同时写，但 Google Sheets Values API 没有基于单元格值的原子比较交换。写前复读能发现已发生的修改，不能提供跨设备同时编辑时的数据库事务保证。避免在同步瞬间编辑同一行；如需多人强并发，后续应增加专用后端或协作锁。

## 扩展

Go 采集器实现 `source.Collector`，在 `cmd/daily-log` 装配。采集器接收时间窗口，返回事件批次和覆盖详情。来源失败由编排层独立捕获，关闭扩展不影响既有采集。若实现可靠活跃时长采集器，再填充 measured_active_duration 和各类分钟数；当前均未知，不作估算。

## 表格同步

`internal/tables` 从 SQLite 构建四个工作表的数据集。所有工作表先校验实际表头、别名与唯一键，再生成仅含变化单元格的更新计划。未知来源、已确认、含本人补充或与上次快照不符的行保留，候选更新进入建议队列。四个分钟列作为用户输入保留，活动占比由事实与实际填写的分钟派生。

Sheets 通过 Go OAuth 客户端直接访问官方 REST API，500 行分块读取，写前复读并使用 RAW 批量更新，读回一致后才提交快照。`auto_layout`、`activity_colors` 控制正文换行、行高与逐行分类颜色，保留列宽、链接和粗体。

Excel 使用 Excelize 在 Go 进程内读取与更新，不调用外部解释器。生成结果先读回核对变化及原有单元格，再检查原文件哈希与占用文件，保留五份备份后原子替换。已有公式、其他工作表及格式保留。已知凭证在新写入内容中脱敏，含凭证的行键跳过。

`cmd/google-oauth` 通过回环地址、随机 state 和 PKCE 获取刷新令牌；`cmd/build-release` 在临时目录按允许列表构建源码与二进制发布包。CI 对 Go CLI、桌面与浏览器构建分别检查。
