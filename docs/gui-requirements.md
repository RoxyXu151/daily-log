# daily-log 图形化版产品需求

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1 草案 |
| 日期 | 2026-11-10 |
| 项目基线 | daily-log Go 版 0.3.0 |
| 目标平台 | Linux、Windows、Android |
| 桌面技术方向 | Go + MyGo 原生 UI |
| 目标用户 | 希望把科研、办公、任务和代码活动集中整理成个人日记的用户 |

## 1. 产品目标

把 AI 对话、Zotero 阅读记录、Todoist 完成记录及其他已授权来源汇入本地活动库。用户可以通过图形界面配置来源、检查运行状态、用日记总表检索事项，并直接编辑和保存日记。SQLite 保存活动、证据及日记版本。Google Sheets 和 Excel 可作为可选同步输出，Markdown 和 JSON 支持本地导出。

日常使用路径为「添加来源 → 测试连接 → 自动或手动采集 → 查看当天事项与证据 → 编辑并保存日记」。系统继续默认按北京时间归档，23:00 整理当天已采集的活动。

## 2. 核心功能

### 2.1 软件接入与活动采集

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| SRC-01 | 接入 Zotero、Todoist、Codex 对话和 Google Calendar，复用现有采集能力。 | 每种来源可独立配置、测试和采集。列表右侧使用明确开关控制是否参与后续采集；界面显示本次测试结果、最近采集时间与覆盖范围。 |
| SRC-02 | 支持 AI 对话的已授权只读接口接入。 | 自动接入仅对已经验证有可用授权接口的服务开放，并说明可访问范围。 |
| SRC-03 | 支持后续扩展办公、科研与代码工具。扩展接入遵循统一活动模型，登记其能力、配置字段和凭证类型。 | 测试用新来源通过注册接入，在来源列表、采集流程及活动表格中可见。日记规则通过统一事件字段消费数据。 |
| SRC-04 | 保留来源、时间、类别、证据类型和原始记录引用。区分任务完成、日程计划、实际讨论和推断。 | 同一输入重复采集时保持稳定事件标识。一个来源失败时，其余来源继续处理，缺口在运行结果和受影响日记中可见。 |

首批来源的采集口径如下。

- **Zotero**采集论文标注、笔记及相关元数据，区分创建与修改。阅读会话可以按标注推断，标注跨度作为证据展示。
- **Todoist**采集本人完成事件，保留重复任务的各次完成记录。历史保留受限时标出覆盖缺口。
- **Codex**记录有证据的讨论及其来源，沿用已授权的只读历史接口。
- **Google Calendar**读取日程安排。已识别的 Todoist 联动记录按现有规则去重。
- **扩展来源**可评估 GitHub、其他代码工具、办公协作和科研软件。纳入顺序由实际需求、授权能力和接口稳定性决定。

### 2.2 可视化表格与日记编辑

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| VIEW-01 | 提供单一「日记总表」数据视图，并在首页展示当天事项和任务状态。日记总表直接承担编辑入口和证据下钻，不提供独立活动流水或论文阅读页。 | 日记总表默认以日期概览展示 AI 归纳的当天高价值事项、总体概要、分类概要和完成任务数。事项与 Todoist 任务同等粒度，同一天的相关多轮对话和跨来源证据必须合并；闲聊、简单查询、重复问答和未展开计划不进入事项。每个事项都经过 AI 提炼，标题不超过 28 字，说明记录事务的具体内容。对话原文保留在证据中。点击日期行展开三时段事项，再按需查看逐轮证据，能按日期和分类筛选。 |
| VIEW-02 | 点击表格记录进入详情，展示生成内容及对应证据。 | 从日记可以打开关联活动，从活动可以定位来源或查看可用的本地证据摘要。活动证据可使用分类管理中定义的任意活动分类，修改后日记总表计数即时刷新，后续重新采集保留手工覆盖。来源缺口、推断和人工编辑有清晰标记。 |
| JRN-01 | 支持按日期打开日记，编辑上午、下午、晚上正文及本人补充，预览 Markdown 并保存。 | 保存后关闭再打开，修改仍在。编辑期间收到新采集结果时，已保存的人工修改得到保护。 |
| JRN-02 | 不再提供用户确认、待复核建议或确认状态。 | 直接保存即成为当前日记；同一日期被另一端先保存时，后保存的一端仍收到版本冲突提示并保留尚未提交的内容。 |
| VIEW-03 | 支持本地 Markdown、JSON 导出，提供 Google Sheets 和 Excel 同步入口及结果查看。 | 输出使用已保存的版本。远端服务或输出文件不可用时，本地编辑与导出仍可完成，界面显示同步状态和重试入口。 |

## 3. 个性化配置

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| CFG-01 | 提供浅色、深色、跟随系统及强调色选择，支持即时预览和恢复默认。 | 强调色同时作用于导航标记、主按钮、选择状态、预览图和工作台组件；保存后重启仍生效。成功、失败、等待和确认状态同时通过文字或图标区分。 |
| CFG-02 | 提供列表式来源管理，每项可点击展开，支持新增连接、编辑参数、启用、暂停、测试连接和移除连接。 | 点击列表项展开对应参数，再次点击收起。暂停与移除会停止后续采集，历史记录仍可查看。移除前说明作用范围，历史清理需要单独操作。无效配置显示对应字段及修正提示。 |
| CFG-02A | 提供独立分类管理，支持新增、重命名、排序和删除分类。 | 分类不是固定枚举。重命名会迁移历史事件、手工覆盖和分类分钟；删除已使用分类时，活动归入受保护的“未分类”。保存后日记总表列、图例、筛选项和活动分类按钮同步更新。 |
| CFG-03 | 提供日志更新配置，支持修改定时整理时间、手动运行、补采范围及进入日志的事件类型。 | 默认北京时间 23:00。修改后显示下次预计运行时间以及实际安装或更新结果。调整纳入规则时可查看影响。 |
| CFG-04 | 支持多个大模型配置，至少可添加、测试、启停和切换，但同一时间只使用一个全局默认模型。配置以卡片列表展示名称、服务地址、模型名、默认状态和操作；日记摘录与 Codex 筛选统一使用该模型。配置项支持本地与云端服务。 | 使用两个可用模型配置完成默认模型切换测试，下一次日记摘录和 Codex 筛选都使用新默认模型。既有日记版本和证据仍可查阅，失败结果能区分凭证、网络和模型响应问题。 |
| CFG-05 | 支持关闭 AI。云端模型启用时展示它处理的数据范围。 | 模型不可用时仍能采集并保留证据，日记显示事项待整理。未经启用的模型不会接收内容。 |

草案把「更新日志的事件」落实为两项设置。用户可以决定**何时更新**，也可以决定**哪些事件纳入日记**。首次模型接入可从 OpenAI 兼容协议开始，同一界面允许保存不同服务和模型。其他协议按独立适配器扩展。

## 4. Modular Bento 界面

首页采用模块化卡片网格。卡片按任务重要程度占用不同面积，沿统一网格对齐。首页突出「今日事项」「原始证据」「完成任务」和「采集来源」，次级卡片显示运行状态与同步结果。点卡片进入对应的详情页。

- **桌面布局**采用侧边导航和宽屏卡片区。日记详情可并排显示编辑区与证据，日记总表使用独立页面呈现。
- **移动布局**将卡片按优先级改为单列。编辑与证据通过页签切换，列表保留关键列，完整字段进入详情。窄屏、软键盘展开和大字号下都能访问保存按钮。
- **状态与反馈**为空列表、运行中、部分失败、未保存、保存成功、版本冲突提供可辨认的界面。主题色变化后仍保留可读文字与清晰焦点。
- **可操作性**桌面支持键盘切换和中文输入法。移动端支持触控、滚动、长文本编辑与中文软键盘，关键动作在目标设备上验收。

## 5. 三端适配

| 能力 | Linux | Windows | Android |
| --- | --- | --- | --- |
| 首页、日记总表查询和日记编辑 | 原生桌面界面 | 原生桌面界面 | 适配触控与窄屏的界面 |
| 来源和模型配置 | 管理当前采集主机 | 管理当前采集主机 | 经授权管理已连接的采集主机，显示操作在哪台主机执行 |
| Zotero 本机 API、Codex CLI 和本地文件采集 | 在具备来源能力的主机执行 | 在具备来源能力的主机执行 | 由已连接的采集主机执行，界面标明来源主机 |
| 定时任务 | systemd 用户任务 | Windows 任务计划程序 | 查看和触发已连接主机的任务 |
| 交付验证 | 构建、安装、启动和实际编辑 | 构建、安装、启动和实际编辑 | 在 Android 实机验证打开、查询、中文输入和保存 |

Linux 和 Windows 采用 MyGo 原生 UI。Android 的首选验证路线是用同一套 Go 界面代码构建 WebAssembly，通过移动浏览器访问已配对的 Go 后端。MyGo 目前的文档列出了桌面构建和浏览器构建，Android APK 的交付方式需要单独确认。安卓浏览器方案须先在实机验证中文输入、软键盘、触控滚动、焦点和保存。若这条路线达不到验收标准，移动界面采用独立适配，继续复用 Go 业务和数据接口。[MyGo 桌面分发](https://mygo.egoist.dev/docs/distribution) · [MyGo 浏览器构建](https://mygo.egoist.dev/docs/ui/browsers)

桌面默认使用本机数据。Android 连接桌面采集主机需要显式启用与配对。跨设备访问需要身份验证和加密传输，界面应说明断连时哪些操作不可用。Android 原生 APK、手机独立采集和离线跨设备同步属于待确认的交付要求。

## 6. 架构和质量要求

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| ENG-01 | 保持高内聚、低耦合。界面负责交互和呈现，应用层负责用例与写入策略，采集器负责来源转换，模型适配器负责协议，存储层负责 SQLite，调度层负责系统定时。 | 日记规则可脱离 GUI、网络和数据库测试。添加一个测试来源或模型适配器时，核心日记规则与表格组件无需修改。 |
| ENG-02 | CLI、桌面界面和移动端调用同一套用例，采用相同的去重、事务边界和版本检查。 | 用同一份输入分别从 CLI 和界面触发，得到一致的事件标识与日记结果。重复任务及并发保存有回归测试。 |
| ENG-03 | 保持对已有数据库的兼容。升级前提供备份途径，数据迁移可验证并可安全重试。 | 用现有数据库副本升级，核对活动数、日记数、证据关联和历史版本。重复迁移后结果保持一致。 |
| ENG-04 | 凭证在后端保管。界面只展示凭证是否已设置，应用日志和导出内容过滤密钥。外部同步只在启用并配置后执行。 | 用测试凭证完成连接测试，并检查界面响应、运行日志和导出文件的脱敏结果。 |
| ENG-05 | 批量采集、重整和导出在后台运行。界面持续显示当前阶段、最近一次结果和可用的恢复操作。 | 运行批量任务时仍可浏览已有日记。单一来源超时和重启补跑时，可以从界面定位原因并验证去重。 |

桌面版使用纯 Go 的 MyGo 原生界面。核心采集、本地日记编辑、Markdown / JSON、Sheets 和 Excel 输出均在 Go 进程内执行；发布包无需额外解释器。表格同步共用人工内容保护与读回核验。[当前项目能力](../README.md) · [现有数据语义](architecture.md)

## 7. 交付顺序与验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| P0 原型验证 | Linux、Windows 原生桌面骨架，以及 Android 浏览器适配试验。 | 两个平台成功打开桌面窗口。Android 实机完成中文输入、表格滚动和样例保存，用结果确定移动交付路线。 |
| P1 桌面核心闭环 | Bento 首页、来源设置和诊断、日记总表、日记编辑与保存、定时和手动运行、基础调色与模型切换。 | 从空配置接入 Zotero、Todoist 与一种 AI 对话来源，采集后可以查证据、编辑日记并导出。Linux 和 Windows 均按流程验收。 |
| P2 三端闭环 | Android 正式适配、主机配对、远程查看与编辑、跨端版本冲突处理。 | Android 与桌面可读取同一日记。移动端完成编辑并保存后桌面可见。并发保存、断连和重连有可重复验收步骤。 |
| 后续扩展 | 更多数据源、模型协议和可选同步方式。 | 每项扩展有单独的授权、兼容性和验收说明。 |

交付验收覆盖四条主路径。

1. **接入**新增来源、验证凭证、测试连接、运行采集、在表格中找到证据。
2. **编辑**按日查看、修改正文并保存。
3. **配置**切换主题、暂停或移除连接、调整定时与事件规则、切换模型并验证下一次运行使用新配置。
4. **跨端**在 Linux、Windows、Android 完成各端规定的流程，复现同一日记的保存冲突和采集主机断连。

## 8. 待确认事项

- Android 是否要求独立 APK，还是接受以实机可用的浏览器界面作为移动交付。
- Android 是否需要脱离采集主机使用，以及外出时是否需要跨网络访问。
- 首批新增的办公、科研和代码工具，以及首批要对接的模型服务。
- Google Sheets 和 Excel 同步是否与纯 Go 核心版同步交付。
